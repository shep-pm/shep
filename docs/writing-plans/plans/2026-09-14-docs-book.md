# Docs book Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the docs sidebar into a book: seven parts, twenty-seven numbered chapters, ordered by when a reader needs a thing rather than by what kind of thing it is. No page prose changes.

**Architecture:** `docs-nav.ts` becomes the single source of truth for a chapter's number, name, part and neighbours. The sidebar, the crumb, the `<title>` and a new next/previous bar all derive from it, so a reorder is one edit rather than twenty-five. Two chapters the later phases will write are listed now as unbuilt, which keeps the numbering final.

**Tech Stack:** Astro 7 (static, no MDX), plain CSS, Node's built-in test runner with native TypeScript type stripping. No new dependencies.

**Spec:** `docs/brainstorming/specs/2026-09-14-docs-verbosity-structure-design.md`

**Previous plan:** `docs/writing-plans/plans/2026-09-14-docs-shell.md`, all five tasks complete.

## Global Constraints

- **Run every command from `web/`.** The worktree root has no `package.json`.
- **No new npm dependencies.**
- **Both build commands, every time.** `npm run build` (which now also runs three check scripts) and `npx astro check`. `astro build` does not typecheck, and a component handed a prop it does not have builds clean and renders wrong.
- **No slug changes and no new routes for built pages.** Every existing URL keeps resolving. The two new slugs added here are unbuilt and must not be linked to.
- **No page prose changes.** This phase edits chapter names, the nav, the layout and two props per page. If a diff changes a sentence of body copy, it is out of scope. `npm run build` prints the prose count per page: the total must stay 44,584.
- **Conventional commit subjects**, `type(scope): summary`. Accepted here: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`. `release-plz` drops whatever does not parse.
- **The two ratchets from the previous plan only grow.** `ENFORCED` in `verify-heading-anchors.ts` holds `["containers"]`; `BUDGETS` in `verify-prose-budget.ts` holds six pages. Do not remove an entry or raise a budget.

```ts
/** One chapter, flattened out of its group and numbered from 1. */
export interface DocsChapter {
  /** 1-based position across the whole book, unbuilt chapters included. */
  number: number;
  /** The part this chapter sits in, e.g. "Get it running". */
  part: string;
  item: DocsNavItem;
}

/**
 * Every chapter in reading order, numbered.
 *
 * Unbuilt chapters are numbered alongside the rest on purpose: a number
 * that shifts when a page lands would invalidate every "chapter 12" a
 * reader has already seen.
 */
export const chapters: DocsChapter[] = docsNav.flatMap((group) =>
  group.items.map((item) => ({ number: 0, part: group.label, item })),
).map((chapter, index) => ({ ...chapter, number: index + 1 }));

/**
 * A chapter and its neighbours, for the crumb, the title and the next bar.
 *
 * `previous` and `next` skip unbuilt chapters, because a bar offering a
 * page that does not exist is worse than one that skips a number.
 *
 * Returns `undefined` for a slug that is not in the nav at all, which is a
 * page that exists but was never filed. `DocsLayout` turns that into a
 * build failure rather than a silently blank crumb.
 */
export function chapterFor(slug: string):
  | { chapter: DocsChapter; previous?: DocsChapter; next?: DocsChapter }
  | undefined {
  const index = chapters.findIndex((c) => c.item.slug === slug);
  if (index === -1) return undefined;
  const built = (c: DocsChapter) => c.item.built;
  return {
    chapter: chapters[index],
    previous: chapters.slice(0, index).findLast(built),
    next: chapters.slice(index + 1).find(built),
  };
}
```

### Task 5: A check that the nav and the pages agree

Three ways this can rot silently: a nav entry marked built whose page does not exist, a page nobody filed in the nav, and an unbuilt entry whose page has quietly been written.

**Files:**

- Modify: `web/package.json`

**Interfaces:**
- Consumes: `chapters` and `chapterFor` from Task 1.
- Produces: nothing other tasks read.

- [x] **Step 1: Write the failing test**

Create `web/scripts/verify-docs-nav.ts`:

```ts
// Regression guard for the docs book.
//
// docs-nav.ts is the only place a chapter is named, numbered or ordered, and
// DocsLayout derives the crumb and the title from it. That makes three
// failures silent rather than loud: a built entry whose page does not
// exist, a page nobody filed in the nav, and an unbuilt entry whose page
// has since been written and is now unreachable from the sidebar.
//
// Runs under Node's built-in test runner with native TypeScript type
// stripping, matching verify-dogs-index.ts.

import { test } from "node:test";
import assert from "node:assert/strict";
import { readdir } from "node:fs/promises";
import { fileURLToPath } from "node:url";
import { chapters, chapterFor } from "../src/data/docs-nav.ts";

const pagesDir = fileURLToPath(new URL("../src/pages/docs", import.meta.url));

/** Page slugs that really exist on disk. `index` is the redirect, not a chapter. */
async function pageSlugs(): Promise<string[]> {
  const files = await readdir(pagesDir);
  return files
    .filter((f) => f.endsWith(".astro"))
    .map((f) => f.replace(/\.astro$/, ""))
    .filter((slug) => slug !== "index");
}

test("every built chapter has a page", async () => {
  const slugs = await pageSlugs();
  const missing = chapters
    .filter((c) => c.item.built && !slugs.includes(c.item.slug))
    .map((c) => c.item.slug);
  assert.deepEqual(missing, [], `built chapters with no page: ${missing.join(", ")}`);
});

test("every page is filed in the nav", async () => {
  const slugs = await pageSlugs();
  const filed = new Set(chapters.map((c) => c.item.slug));
  const unfiled = slugs.filter((slug) => !filed.has(slug));
  assert.deepEqual(
    unfiled,
    [],
    `pages missing from docs-nav.ts, so unreachable from the sidebar: ${unfiled.join(", ")}`,
  );
});

test("no unbuilt chapter has quietly grown a page", async () => {
  const slugs = await pageSlugs();
  const written = chapters
    .filter((c) => !c.item.built && slugs.includes(c.item.slug))
    .map((c) => c.item.slug);
  assert.deepEqual(
    written,
    [],
    `these have a page but are still marked built: false, so the sidebar will not link them: ${written.join(", ")}`,
  );
});

test("chapter numbers run 1..n with no gaps and no repeats", () => {
  assert.deepEqual(
    chapters.map((c) => c.number),
    chapters.map((_, i) => i + 1),
  );
});

test("no two chapters share a slug", () => {
  const slugs = chapters.map((c) => c.item.slug);
  const repeated = slugs.filter((s, i) => slugs.indexOf(s) !== i);
  assert.deepEqual(repeated, [], `repeated slugs: ${repeated.join(", ")}`);
});

test("neighbours skip unbuilt chapters in both directions", () => {
  for (const { item } of chapters) {
    const found = chapterFor(item.slug);
    assert.ok(found, `chapterFor lost ${item.slug}`);
    assert.notEqual(
      found.next?.item.built,
      false,
      `next from ${item.slug} is unbuilt, so the bar would link a 404`,
    );
    assert.notEqual(
      found.previous?.item.built,
      false,
```

## What was done differently, and why

**One defect found, in a tool rather than in the docs.** Checking that the
prose count had moved by exactly the nine heading edits that caused it,
eight pages matched the prediction and `folds` moved by three without its
heading being touched. `folds`'s description reads `fold:<name> reaches it
from any verb`, and `proseWords` stripped tags with `/<[^>]*>/`, which
stops at the first `>` it meets: the one inside that quoted attribute. The
tail of the `<DocsLayout>` invocation had been counted as prose since the
counter was written. The corpus total was 44,584 and is 44,559; the 25
missing words were never prose. Fixed in its own commit before the nav
work landed.

The lesson is worth carrying: a number a tool produces is a measurement,
and a measurement can be wrong in a way that reads as a fact. This one was
out by 0.06 percent and did not matter. The same defect on a page with a
tight budget would have.

**The rebuild moved item objects rather than retyping them.** `source`,
`spec` and `api` back the reference pills, and a transcription slip there
is invisible until a pill 404s. Verified by field count against the
previous commit: spec 21 and 21, api 6 and 6, `built: true` 25 and 25,
with `slug` and `source` each up by exactly the two new entries.

## Left for later phases, deliberately

- **In-prose link text still names the old chapters.** Nine pages say "Your first Flockfile", five say "Getting started", five say "Overrides". Those are sentences, and this phase changes no sentences. Each gets fixed by the phase that rewrites its page.
- **The per-page "Where to go next" cards keep their current targets.** The chapter bar answers "what next"; the cards answer "what else". Trimming a page's cards to genuinely related reading belongs with that page's rewrite.
- **`https://github.com/shep-pm/shep` is hardcoded in five places** (`CtaFooter`, `Nav`, `DocsHeader`, `StillStuck`, and `ReferencePills`, which already holds it as a private `const REPO`). Exporting one constant touches four files for no behaviour change, so it is noted rather than folded in here.
